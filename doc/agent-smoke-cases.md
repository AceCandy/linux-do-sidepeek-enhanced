# Agent Smoke 用例库

这份文档记录当前可复用的 `agent-browser` Chrome smoke 用例。

规则：

1. 每个用例都有固定 ID
2. 每个用例只写稳定断言
3. 每次修线上回归，补一个对应回归用例

## 1. 前置条件

### 浏览器

```bash
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-codex
```

### 扩展

1. 打开 `chrome://extensions/`
2. 开启 `Developer mode`
3. `Load unpacked`
4. 选择仓库根目录
5. 代码改动后点击 `Update`

### agent 连接

```bash
agent-browser --cdp 9222 get url
agent-browser --cdp 9222 snapshot -i
```

### 批量执行

```bash
bash scripts/agent-smoke.sh --cdp-port 9222
```

指定用例：

```bash
bash scripts/agent-smoke.sh --cdp-port 9222 --cases AGENT-CHROME-001,AGENT-CHROME-006
```

### AGENT-CHROME-010：最新回复刷新按钮

范围：
`#6` 最新回复刷新按钮

步骤：

1. 打开任一列表话题
2. 在 `选项` 中切到 `智能预览`、`完整主题`、`首帖 + 最新回复`
3. 确认工具栏出现 `刷新` 按钮
4. 点击 `刷新`
5. 待刷新完成后，在中间列表再次点击刚才打开的同一主题标题

断言：

1. 点击前 `刷新` 按钮存在、可见、可点击
2. 点击后按钮立即进入禁用态，并显示 `刷新中...`
3. 刷新完成后按钮恢复为 `刷新`
4. 再次点击同一主题标题后，应触发与刷新按钮一致的刷新态：按钮立即变成 `刷新中...`
5. 二次刷新完成后按钮再次恢复为 `刷新`
6. 两次刷新过程中 `location.href` 都保持在列表页，抽屉不关闭

定位窗口刷新回归（固定数据：`node scripts/check-preview-browser.cjs`）：

1. 默认顺序打开带楼层定位的长帖，接口先返回 35 / 41 条帖子，确认目标楼层保留。
2. 将接口总数及帖子 ID 流更新到 43 条，点击右下角刷新；确认请求重新获取数据，按钮恢复可用。
3. 滚动到底部，确认继续请求缺失帖子，新增的第 42、43 楼可见，无需关闭重开；楼层无重复且保持升序。
4. 页面 URL 和定位链接保持不变；不再显示“当前抽屉预览了……完整内容可点右上角……”提示。

### AGENT-CHROME-019：左侧信任等级状态

固定页面验证命令：`node scripts/check-status.cjs --browser`。

1. 左侧显示信任等级面板，四类指标正确区分下限要求和上限限制，千位分隔符正常解析。普通指标单行显示名称和数值，行高不超过 30px；状态通过数值颜色、悬停提示及无障碍说明表达，不单独占行。长名称允许换行。
2. 默认收起且不请求；鼠标悬停展开，移到内容区保持展开，移开收起。临时展开不保存状态；点击固定并保存，再次点击或 Esc 取消固定。触屏不触发悬停，键盘 Enter 可固定；面板内仍有焦点时不得因鼠标移开关闭，焦点离开后收起。390px 视口展开不溢出。
3. 手动刷新期间按钮禁用；自动请求至少间隔五分钟，后台标签页不自动请求。
4. 登录页、验证页、损坏数据不显示虚假的零值；失败后可重试，并能通过安全的新标签链接打开 Connect。
5. 在线保留项：与 Connect 原页面逐项核对数字，在原站实际阅读后观察统计变化；仅加载主题 JSON 不能作为已读成功证据。

### AGENT-CHROME-020：可见标题预取与统一缓存

固定页面命令：`node scripts/check-preview-browser.cjs`；逻辑断言：`node scripts/check-preview.cjs`、`node scripts/check-cache.cjs`。

1. 当前视口主题标题才排队；每秒最多两个、并发最多两个，预取不携带 `track_visit` 或浏览请求头，且不发送 `/topics/timings`。
2. 切到后台或整页模式不再启动预取；滚出视口的未开始条目不请求。动态新增或更新的标题仍可预取。
3. 点击已缓存/正在预取的主题，不重复请求首批正文；缺少目标楼层时补目标数据。取消旧加载后不会覆盖新主题。
4. 100 个主题上限、最近使用淘汰和十分钟过期；不同楼层链接共享主题数据，定位及各自滚动位置正确，iframe 占位不写入正文缓存。

### AGENT-CHROME-021：智能预览实际阅读上报

1. 前台阅读首帖后产生 `/topics/timings`，只含实际可见楼层和毫秒时长；加载但未见的回复不应入报。
2. 游客、后台、失焦、设置/回复/图片浮层遮挡、长时间无操作不累计阅读。
3. 切帖和关闭提交旧主题剩余记录；阅读状态关闭后不继续上报。整页模式不额外上报。
4. 末楼/最新回复仍按真实可见楼号上报，不伪造中间楼层；接受站点按最高楼推进已读游标的语义。
5. 网络失败后不重放不确定的批次，后续请求降频；CSRF 会话变更后不发送旧会话记录。
6. 在线保留项：确认服务端接受上报，刷新列表检查已读位置，再对比 Connect 指标；固定页面通过不代替真实入账验证。

### AGENT-CHROME-022：智能预览图片轮播

1. 打开含 `.d-image-grid[data-mode="carousel"]` 的主题，初始仅展示第一张；左右按钮循环切换，圆点可直接选图并同步当前状态。

3. 同帖多个轮播互不影响；单图隐藏控制条，空轮播不报错，普通 grid 和轮播外图片不受影响。
4. 在追加回复、缓存重新打开及窄屏下检查上述交互；真实帖参考 `https://linux.do/t/2891303`。
5. 固定页面回归：`node scripts/check-preview-browser.cjs`。该检查不代替真实帖子和原站样式兼容验证。

### AGENT-CHROME-023：原站正文组件优先渲染

1. 智能模式打开真实主题，确认正文容器具有 `ld-native-body`，轮播使用原站 `.d-image-carousel`，不生成 iframe 或自制轮播按钮。
2. 检查原站图片放大、折叠、代码块与普通链接；原站模式不被扩展图片点击处理抢占。
3. 切帖、追加回复、关闭再打开，确认正文正常且旧组件销毁；原站页面的正文与交互不受影响。
4. 模块不可用或挂载失败时保留旧智能正文，不出现空白；固定页面命令 `node scripts/check-preview-browser.cjs` 覆盖生命周期和回退。
5. Chrome 扩展通过 MAIN world 注入桥，油猴内嵌同一桥；Firefox 与油猴在线会话需要分别验证。原站内部模块升级仍可能触发回退。

本次真实 Chrome 页面验证：使用项目 `buildPostCard`、CSS 与正文桥在临时抽屉中挂载主题 2891303，原站轮播显示 5 张、可切换、图片放大正常，关闭后恢复回退正文；未验证安装后的完整扩展上下文或其他站点插件。临时节点和测试标签页已清理。

### AGENT-CHROME-024：紧凑操作、返回顶部、表情与 Boost

1. 智能正文滚动后点击顶部向上箭头，抽屉滚回顶部，原页面位置不变；整页模式隐藏该入口，窄屏仍可用。
2. 单层楼只显示一排表情汇总、回复数、`|`、复制/书签/举报/回复按钮，不显示楼层阅读量或重复点赞计数。
3. 点击表情汇总只打开选择器，不提交请求；选择表情发送一次请求，切换及取消依据服务器返回更新图标、计数和选中状态。403 等错误不回退到其他写接口。
4. 原站提供 Boost 时展示气泡和火箭入口；输入框、表情面板不被抽屉遮挡，点击取消或 Esc 不误关抽屉。关闭或切帖销毁对应组件，原站更新同步至内存帖子。
5. 主题 `2879086` 的长代码在 320px 抽屉中可横向滚动，楼层不超宽，回复按钮可见；原生正文及回退正文均需验证。
6. 固定页面回归：`node scripts/check-preview-browser.cjs`。真实页面验证使用项目代码、样式和桥挂载临时抽屉，通过表情图片、Boost/表情面板打开与取消、代码横滚和单排布局；没有提交真实点赞、Boost、删除或举报。Firefox、油猴管理器实装及完整扩展隔离上下文未验证。
